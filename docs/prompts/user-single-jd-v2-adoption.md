# 单份 JD 提示词 v2：采用说明

用户原稿保存在 `user-single-jd-v2.md`，未改写。生产使用的是 `lib/analysis-prompt.ts` 中的 `ANALYSIS_INSTRUCTIONS`，版本为 `work-language-v10`，由 `lib/model-reading.ts` 直接发送至现有 DeepSeek 接口。归档文本不是第二层系统指令。

## 采用的交付要求

- 每条职责保留确切原文，配 8–12 字左右短标题、具体对象、可操作步骤、用途、业务微场景、交付和可观察的质量判断。例子直接从用户问题、客户需求或业务故障写起，不机械用“假设”开头。
- 对象要解释抽象词背后的材料。数字岗位可以是答案与评分的对照、待核对的检索片段；制造、零售、照护等岗位使用其自身的零件、顾客、人员与场景，不强行电脑屏幕化。
- 新生成内容提供两份小型准备作品和两道业务追问，另有一至两个值得问招聘方的问题，及可能回答 A/B 会怎样改变具体工作。
- 每条职责下连接相关词条；自然解释尚不清楚的范围，不逐段追加免责尾巴。
- 社会学卡片摘要不超过 60 字，展开约 150–200 字。论点由 JD 原文关系支持；参考做法和生成例子不能回流成证据。
- 所有内容保留中英双语；英文引号内的搜索词也翻译，原文只留在证据字段。

## 为避免把文风当作证据而作的调整

原稿示例帮助确定颗粒度，但不照抄其未经证实的公司内部事实：飞书/腾讯文档、内部编排画布、外包人员、日志权限、样本数量、周报频次、近一半工作时间等，只有原文或外部资料支持时才写成事实。示例里可以有少量自拟数字，但明确放在“情境示例”字段，不当作已发生结果。

“做得好”比较能检查的结果，不许承诺 return offer；A/B 比较任务比重、技能、资料权限与协作接口，不把清洗/质检贬为低价值，也不保证工具工作就是核心岗位。机评与人评都可能出错；一致率不是天然真值。不会把“协助”解释成没有判断权。

“说人话”不等于攻击同事。保留具体动作，去掉“分锅”“算账”和人为杜撰的对立。自然的边界提醒说清要问什么，界面以“参考做法”“情境示例”“可能回答”区分建议、例子与已知事实。

## 兼容与验收

保留原 `task/quote/output/check/object/action/purpose/scenario` 字段及 `work-language-v2` 储存协议，新增可选 `depth.sociologySummary` 与 `depth.sociologyConceptId`。旧记录可以没有摘要，有社会学段落的新生成必须提供摘要和一个已核实概念，且进入既有原文、权限、双语校验；依据不足时，正文和摘要均为空、概念为 null、锚点为空。新生成在信息充分时给两份准备材料和两道练习，信息不足可少写，旧记录仍可读取。

前端优先显示新摘要；旧记录继续从原分析取开头。Markdown 与 PDF 共用导出内容，包括摘要、展开、每条职责的词语说明、示例与建议标签。

离线契约检查不能证明分析准确率。R6 仅用一份腾讯微信搜索 Agent 用户原 JD 做真实调用，最多两次现有流程请求；模型输出与审阅结论保存在本地 `.sites-runtime/v9-live-r6/`，不上传用户语料。失败如实保存，不用修改阈值或多次重试来制造成功。

## 第三稿的最终调整

同时采用 `user-single-jd-v3.md` 的短句规则和实施取舍：字段显示“对象／具体做什么／为什么要做／举个例子／最后交什么／做到什么算好”；不用对仗排比、虚构内行情绪或泛化黑话。面试回答思路最多三句；反问最多三项。没有用户背景时给条件式建议，不替用户决定投不投。

社会学段落可整组省略；保留时摘要最多 60 字、正文指导上限 200 字，按依据、概念在岗位中的作用、具体减弱条件和实际追问组织。概念 ID 只可选择固定书目表中的已核实来源，链接由程序附加，不接受模型生成作者或链接。当前清单很小，不能为匹配清单硬套概念。

书目信息和概念使用范围于 2026-11-08 依据出版社页面核实：

- Bowker & Star (1999), *Sorting Things Out*: https://mitpress.mit.edu/9780262522953/sorting-things-out/（页面同时列出 1999 精装与 2000 平装）。
- Abbott (1988), *The System of Professions*: https://press.uchicago.edu/ucp/books/book/chicago/S/bo5965590.html 。
- Hochschild (2012 [1983]), *The Managed Heart*: https://www.ucpress.edu/books/the-managed-heart/paper（链接为 2012 第三版，不把版次写成 1983 初版页面）。

不会照搬用户示范里的 20 条题却有 72% 的简单一致率、随机重跑必完全一致、提成即制造同意、护理沟通通常不进考核等断言。自动校验能检查原文锚点、部分事实关系与语言完整性；它不能替代对这些解释的独立专家审阅。

## 实际请求体的收紧

R6 使用的主提示词源码为 30,907 字符，没有拼接用户长 few-shot。R6 未完成有效验收后，将重复证据约束整理为一份契约，缩至 13,850 字符（减少约 55%）。四条职责的正文目标收紧为约 1,400–1,900 个中文字，默认 3–4 个词条；保留具体动作、短场景与准备建议。API 的模型、thinking 参数、两次调用上限和生产超时均未放宽。R6 执行时源码另存于本地测试目录，可与 R7 比较。

R6 评测脚本响应副本读取超时而中断，没有可评分的完整输出；它没有记录每次请求起止，不能据此虚构精确延迟或调用数。R7 改为逐次记录 HTTP 状态、开始时间、首个正文时间、结束原因和 token usage，只保存最终回答片段，不保存推理正文或密钥。最终是否可发布由 R7 的实际文本审阅决定，不以格式检查代替。
