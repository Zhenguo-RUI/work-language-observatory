# 工作语言观察站：研究流程与两页规范

这个 skill 管两件事：research/ 下的分析怎么做；「工作关键词」「研究观察」两页上能写什么、怎么写。

## 先读什么

- 改代码前先遵守仓库根目录的 AGENTS.md。
- 细则按需读：
  - `references/pages.md`：两页的结构、字段、数字怎么进页面。改页面前读。
  - `references/methods.md`：默认研究设计，以及每种方法的做法、要交的文件、页面上报告什么、不能怎么说。跑或改脚本前读。
  - `references/writing.md`：中英文文风和改写示例。写任何页面文字前读。
  - `references/bibliography.md`：可以引用的文献和各自的用途。加引用前读。
  - `templates/codebook.md`：编码手册骨架。

## 两页的读者

- **工作关键词**：求职者查一个词时用。一屏内要能看到：这个词出现在哪些工作里，旁边常跟哪些词，主要有几种用法，可以问对方什么。这一页同时是研究的证据入口。
- **研究观察**：研究读者是想核对方法和数据的人。页面说明研究问题、测量、验证和结论范围。
- 两页都以作者本人的名义公开。页面上每个数字、每条引用、每处方法描述，均须能追溯到证据。

## 硬规则

做不到其中任何一条，就停下，告诉用户卡在哪一步、缺什么。

1. **统计数字只来自脚本输出。** 页面文案里的数字一律引用 `research/aggregates/stats.json` 的键（写法见 pages.md），不手写。旧提示词、示例、草稿里的数字都不是结果，不进页面。"过半""三成""大多数"这类说法同样要有对应的键。
2. **人工标签只能由人填。** 到了需要人工抽查、编码或裁定的步骤，生成表格和填写说明，然后停下等用户。不得自己填写，不得模拟第二位编码员，不得把模型输出写进人工标签文件。
3. **模型标签验证后才能用。** LLM 编码的结果，要先和人工金标准对照、报告一致率和主要错误类型，才能用于页面上的比例。比例和置信区间用 DSL 估计（见 methods.md 第 7 节），不直接平均模型标签。
4. **原始语料不出本机。** `research/private/` 不进 git（仓库的 .gitignore 已忽略所有 `private/` 目录，提交前仍要核对）。仓库和页面只放聚合结果、词语级统计、经人工确认的去识别释义。页面上不出现公司名、联系方式、原文整句、记录 ID。
5. **假设先写后测。** 开始编码金标准前，把问题、假设、分析计划写进 `research/preregistration.md`，单独提交一次。看过数据后新增或改动的假设标为"探索性"，不能当作事先假设汇报。
6. **不做因果推断。** 这份数据没有处理分配机制，没有可比的多期结果，也没有可靠的薪资字段。不跑、不写匹配、断点、双重差分，也不写"净效应""导致""使得"。用户要求时，说明需要什么数据，然后停下。
7. **文献只用核实过的。** 只引用 bibliography.md 里的条目，而且只用来支持该条目写明的用途。要加新文献，先打开 DOI 或出版社页面核对作者、年份、题目和出处；核对不了就不引用，并告诉用户。
8. **分析能复跑。** 固定随机种子。每次运行在 `research/logs/` 记下脚本的 git 版本、输入文件哈希、模型名称和调用日期、提示词文件哈希、温度和输出文件。日志里不写密钥，不写原文。

## 目录

```
research/
  private/        原始语料、全文、KWIC、含原文的标注表、模型原始回复（不进 git）
  config/         terms.yaml（词表、匹配与排除规则、分组）、occupations.yaml、prompts/（带版本号）、copy-files.json
  scripts/        按步骤编号的脚本，00_ 开始
  annotations/    人工标注结果，只存 occurrence_id（哈希）和标签，不存原文
  codebook/       编码手册 v1、v2……，每版附变更记录
  aggregates/     可公开的聚合结果（JSON），含 stats.json
  logs/           运行记录和 progress.md
  preregistration.md
```

注意：仓库 .gitignore 里有 `outputs/`，任何叫 outputs 的目录都不会被提交，所以公开结果放 `aggregates/`，不要改名。

公开链路：`research/aggregates/` → `scripts/build-public-study.mjs`（新建）→ `data/public-study.json` 和 `public/research/` 下的下载文件 → 页面。`lib/` 里的页面文案通过 stat 键取数字。

## 工作顺序

按顺序做，不跳步。每步做完跑对应检查，并在 `research/logs/progress.md` 记一行：日期、步骤、产出文件、是否在等人工。

0. **核对输入。** 语料文件在不在，有哪些字段，三个来源各多少条，有没有职位名、雇主、城市、发布日期。来源数据集的名称、采集时间、使用许可，有记录的写进 `research/aggregates/inputs.json`，没记录的列出来问用户，不猜。
1. **和用户确认研究设计。** 把 methods.md 里的默认问题、假设、焦点词、职业分类方案、词表分组给用户看。确认或修改后写进 preregistration.md 并提交。
2. **词表计数与精确率。** 按 `config/terms.yaml` 计数。每个词随机抽 20 条命中，生成抽查表，停下等人工。回来后算精确率和 Wilson 区间。精确率低于 0.85 的词，改排除规则，重新抽查。
3. **职业与层级。** 职位名映射到职业大类和层级，规则优先，剩下的交给模型。随机抽 100 个职位名生成核对表，停下等人工。回来后报告准确率和主要错分。
4. **搭配词。** KWIC 只在本机生成。按职业大类比较搭配词（methods.md 第 3 节），只公开达到门槛的词语和统计量。
5. **编码手册与金标准。** 从 templates/codebook.md 起草 v1，先用开发样本试编、修改。然后按 methods.md 第 5 节抽金标准样本，生成双人编码表，停下等人工。回来后算各维度的 Krippendorff's α。低于 0.667 的维度，改手册出新版，换一批样本重编，不能删掉维度了事。
6. **模型编码与对照。** 提示词冻结后，对全部出现处编码。与裁定后的金标准比较，报告准确率、宏 F1、混淆矩阵，并和人与人的一致率并排列出。
7. **估计。** 用 DSL 估计各假设对应的比例和差值，报告估计值、95% 置信区间、模型编码总数和金标准数。
8. **稳健性。** 模板句检测；去掉模板句后重估；按职业大类、平台、文本长度分层。写清哪些结论变了、变了多少。
9. **写页面。** 按 pages.md 和 writing.md 改两页。改页面结构时同步改 `scripts/check-public-study.mjs`：旧断言只在对应结构确实删除时才去掉，新断言至少同样严格。最后跑全部检查。

## 需要停下来问用户的情况

- 第 2、3、5 步需要人工的时候
- 来源数据集、采集时间或使用许可不清楚
- 某个维度的 α 低于 0.667，或模型与金标准的一致率明显低于人与人
- 看过数据后想改假设、换焦点词、改编码维度
- 结果和页面上现有的说法相反（照实写，但先告诉用户）
- 用户要求因果估计、薪资效应，或要展示原文、公司名
- 要引用 bibliography.md 之外的文献
