## 1. 编码单位

一次出现 = 焦点词 + 它所在的分句。分句按句号、分号、叹号、问号、换行和条目编号切分。

- 编码员可以看整份广告，但只对这一处出现下判断。
- 同一分句里焦点词出现两次，只编一次。
- 焦点词只出现在职位名里、正文没有，不编。

## 2. 编码员看得到什么、看不到什么

- 看得到：这处出现所在的分句（高亮）、整份广告正文、职位名。
- 看不到：平台、公司名、模型标签、另一位编码员的标签。

## 3. 维度

每个维度写：定义、选项、判断规则、例子、容易混的情况。例子只能来自开发样本，不能来自金标准。

### D1 指向

这处出现说的是人，还是别的东西？

- A 劳动者要求：应聘者应具备的能力、品质或经历。例：〈开发样本例子〉
- B 工作内容：要做的事，焦点词描述做法或范围。例：〈开发样本例子〉
- C 非劳动者：指系统、设施、产品、网站、公司等。例：〈开发样本例子〉
- D 无法判断

判断规则：A 和 B 都沾边时，看焦点词修饰的是人（能力、品质、经历）还是事（任务、流程）。修饰人选 A，修饰事选 B。D1 选 C 或 D 时，D3 到 D6 不编。

### D2 语气

- 必须：要求、需要、须具备、写在"任职要求"里且没有"优先"字样
- 优先：优先、加分、更佳
- 职责陈述：写在"工作职责"里
- 公司承诺：写在福利、发展、团队介绍里
- 其他

### D3 点名的协作对象

判断范围：焦点词所在条目，以及前后各一条。

- 是：出现了具体的人或部门。例如上级或主管、同事或团队、其他部门、客户或用户、供应商或渠道、研发或算法团队、候选人或面试官。
- 否：没有点名，或只有泛称（"相关人员""各方"算否）。

子项（选"是"时多选）：上级 / 同级或团队 / 其他部门 / 外部客户或用户 / 外部合作方

### D4 结果责任

判断范围：焦点词所在条目。

- 是：写明要对一个结果负责，或要跟到结束。例如确保、达成、对……负责、跟进到关闭、按时交付。
- 否

### D5 决定权

判断范围：整份广告。

- 明确有：写明可以决定的事项，例如标准、预算、人员、优先级、例外处理、停工。
- 明确受限：写明要报批，或写为协助、配合他人完成同一件事。
- 未写

"未写"不等于"没有"。页面上只能说"广告没有写"。

### D6 词专属维度（可选）

- 闭环 · 回路类型：异常跟进 / 业务流程 / 数据或模型回路 / 其他
- 抗压 · 压力来源：工作量 / 时限 / 依赖他人配合 / 客户或现场 / 未写

## 4. 拿不准时

- 先按判断规则走；规则没覆盖到的，选更保守的选项（D3 选否，D5 选未写），并在备注栏写原因。
- 备注里的疑难情况，在裁定会上讨论，结论写进下一版手册。

## 5. 裁定

- 两位编码员各自编完再对照。
- 分歧逐条讨论，记录最终标签、理由，以及是否因为手册不清楚造成。
- 因为手册不清楚造成的分歧，改手册，出新版本。
